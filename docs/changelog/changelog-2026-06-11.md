## Naur "Programming as Theory Building"을 10계명에 병합

- 목적: 기존 10계명은 코드 편집 규율(작게, 외과적으로, 검증하고)을 잘 잡지만, Naur가 말한 두 가지 실패 모드를 놓치고 있었다. (1) 작업 재진술만 하고 코드가 모델링하는 도메인을 이해하지 않는 에이전트, (2) 테스트는 통과하지만 프로그램의 설계 의도(theory)와 싸우는 패치로 구조를 부패시키는 에이전트.
- 결정: 룰 1을 "Build the theory first / 이론부터 세워라"로 재정의해 프로그래밍 = 이해 구축이라는 선언과 도메인↔코드 매핑 설명 의무를 앵커로 삼았다. 룰 5에 "설계 의도를 따르라 — 구조와 싸우는 패치는 결함"이라는 절을 추가했다. 문서 스타일의 why 항목은 "다음 읽는 사람이 이론을 재구성할 수 있게"로, changelog 규칙은 "기각한 대안 포함"으로 날카롭게 했다. README 양쪽에 실패 사례 1줄과 Naur 1985 논문 링크를 추가했다.
